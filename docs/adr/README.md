# Architecture decisions

These records capture decisions from the founding discussion and subsequent
standardization work. `accepted` describes agreement on the direction;
implementation is pending unless the repository demonstrates otherwise.

| ADR                                                         | Decision                                                  | Status   |
| ----------------------------------------------------------- | --------------------------------------------------------- | -------- |
| [0001](0001-create-project-infra-as-a-separate-project.md)  | Develop project-infra alongside standards                 | accepted |
| [0002](0002-reconcile-current-project-state.md)             | Apply current conventions to the observed project         | accepted |
| [0003](0003-install-and-version-at-project-scope.md)        | Install and version the package at project scope          | accepted |
| [0004](0004-use-native-metadata-and-existing-owners.md)     | Use native metadata and existing ownership                | accepted |
| [0005](0005-separate-portable-content-from-integrations.md) | Separate portable content from app integrations           | accepted |
| [0006](0006-prioritize-instruction-quality.md)              | Prioritize instruction quality and native checks          | accepted |
| [0007](0007-make-documentation-part-of-the-product.md)      | Make accessible documentation part of the product         | accepted |
| [0008](0008-adopt-an-iterative-standards-baseline.md)       | Adopt an initial baseline and iterate through project use | accepted |

See [the contribution guide](../../CONTRIBUTING.md) for the record lifecycle and
[the RFCs](../rfcs/README.md) for implementation proposals.
